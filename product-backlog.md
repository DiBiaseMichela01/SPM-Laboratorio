# Product Backlog

## Project

Tourism Application — SPM Laboratory

## Overview

This document contains the main User Stories that I plan to develop during the project.

I have organised the work into four Sprints, following the requirements of the assignment. The backlog will help me keep track of the features that need to be implemented and monitor my progress.

The User Stories have been prioritised based on User Value, Dependencies, and Logical Flow, following the course guidelines. Story Points have been estimated using relative estimation, with US-02 (User Login) as the two-point reference story. These estimates are preliminary and may be revised during the project.

## Estimation Method

Story Points were assigned using Relative Estimation, following the course guidelines. US-02 (User Login) was selected as the reference story and estimated at 2 Story Points. All other User Stories were compared with this reference according to their relative effort, complexity, and uncertainty.

The reference story was decomposed into five tasks, with an estimated total of 28 hours. This provides an initial Points-to-Hours Approximation of approximately 14 hours per Story Point for sprint planning, not a fixed conversion.

Planning Poker was not applied because this is an individual project and there are no other team members with whom to compare estimates. Estimates may be revised as the project progresses.
